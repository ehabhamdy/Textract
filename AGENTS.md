# AGENTS.md

## Project overview

TextExtractor is a native Swift 6 macOS menu-bar app. It lets the user select a screen region with the system `screencapture` tool, recognizes text locally with Apple's Vision framework, and writes successful OCR output to the system clipboard.

Keep the default product small, native, and privacy-preserving. OCR must remain on-device unless a future feature explicitly introduces and clearly communicates a different processing path.

## Source of truth and repository map

- `project.yml` is the source of truth for targets, packages, deployment settings, signing settings, and other Xcode project configuration.
- `TextExtractor.xcodeproj` is generated by XcodeGen. Do not hand-edit `project.pbxproj`; change `project.yml` and run `xcodegen generate`.
- `TextExtractor/App/` contains lifecycle and orchestration code.
- `TextExtractor/Capture/` owns interactive screen capture and temporary capture files.
- `TextExtractor/OCR/` contains the extraction protocol, Vision implementations, and text post-processing.
- `TextExtractor/Clipboard/` owns pasteboard writes.
- `TextExtractor/MenuBar/` and `TextExtractor/Settings/` contain SwiftUI UI.
- `TextExtractor/Support/` contains preferences, shortcut definitions, `Info.plist`, and entitlements.
- `scripts/build_app.sh` regenerates the project and creates a Release app in `dist/`.
- `README.md` documents the current app. `plan.md` and `inspiration.md` are design history; do not assume every proposed item is implemented. `PRODUCTIONIZATION.md` is a release checklist.
- `landing/` is a separate static marketing page. Avoid changing it during app work unless the task includes the website.

Do not edit or commit Xcode user-state files under `xcuserdata` or `.xcworkspace/xcuserdata`.

## Supported environment

- Deployment target: macOS 14.0+
- Language mode: Swift 6
- Project generator: XcodeGen
- External package: `KeyboardShortcuts`, currently resolved to 2.4.0
- App style: menu-bar-only (`LSUIElement`); absence from the Dock is intentional
- Distribution model: currently non-sandboxed, hardened-runtime app intended for direct signing and notarization

Structured document recognition uses APIs available only on macOS 26+. Keep those types and calls behind `@available(macOS 26.0, *)` declarations and `#available(macOS 26.0, *)` runtime checks. The generic `VNRecognizeTextRequest` path must continue to work on macOS 14 and later.

## Build and verification commands

Run commands from the repository root.

```bash
# Regenerate the Xcode project after changing project.yml, targets, or dependencies
xcodegen generate

# Fast compile verification without requiring a signing identity
xcodebuild \
  -project TextExtractor.xcodeproj \
  -scheme TextExtractor \
  -configuration Debug \
  -destination 'platform=macOS' \
  CODE_SIGNING_ALLOWED=NO \
  build

# Build a local Release app bundle in dist/TextExtractor.app
./scripts/build_app.sh
```

There is currently no test target. If a change adds testable logic, add an XCTest target in `project.yml`, place tests in a dedicated `TextExtractorTests/` directory, regenerate the project, and run:

```bash
xcodebuild \
  -project TextExtractor.xcodeproj \
  -scheme TextExtractor \
  -destination 'platform=macOS' \
  CODE_SIGNING_ALLOWED=NO \
  test
```

Do not run `./scripts/build_app.sh` merely to verify a source edit: it modifies generated/project output and replaces `dist/TextExtractor.app`. Use the unsigned Debug build first.

## Runtime architecture and invariants

The main flow is:

1. `TextExtractorApp` creates the menu-bar scene and Settings scene.
2. `AppController` receives menu or global-shortcut actions and prevents overlapping captures.
3. `ScreenCaptureService` invokes `/usr/sbin/screencapture -i -x` and returns a unique temporary PNG URL.
4. A `TextExtractionEngine` implementation performs OCR.
5. `ClipboardService` replaces clipboard text only after OCR succeeds.
6. `AppController` removes the temporary file and reports success or failure.

Preserve these behavioral invariants:

- Only one capture/OCR flow may run at a time.
- User cancellation is normal control flow: show no failure alert and leave the clipboard unchanged.
- Failed capture or OCR must leave the clipboard unchanged.
- Every temporary capture must be removed after use, including error paths.
- Empty OCR results must become `TextExtractionError.noTextFound`, not a successful empty clipboard write.
- Screen selection should continue to use the native interactive UI unless a task explicitly changes the capture design.
- The capture and clipboard layers must not depend on a specific OCR implementation.
- Recognition languages, custom words, line-break behavior, and OCR mode come from `AppPreferences` at capture time so settings changes take effect without relaunching.

## Swift and concurrency conventions

- Follow the existing Swift API Design Guidelines and four-space indentation.
- Prefer small value-type services (`struct`) and protocol boundaries where substitution or isolated testing is useful.
- Keep UI state and AppKit presentation on `@MainActor`. `AppController` and `LaunchAtLoginController` are intentionally main-actor isolated.
- Keep CPU-heavy or blocking OCR work off the main actor. Values crossing concurrency boundaries must satisfy Swift 6 `Sendable` checking.
- Do not weaken concurrency diagnostics with unchecked annotations unless the safety argument is documented and no safer design is practical.
- Prefer `async`/`await` and checked continuations for callback APIs. A continuation must be resumed exactly once on every path.
- Use `LocalizedError` cases for user-facing failures. Treat capture cancellation separately from actual errors.
- Avoid force unwraps and force casts in app code.
- Keep views declarative and thin. Put capture/OCR orchestration in controllers or services, not SwiftUI view bodies.
- Use availability checks for every API newer than the macOS 14 deployment target.

## Preferences and project configuration

When adding a preference, update all relevant layers together:

1. Add a stable key to `PreferenceKeys`.
2. Register a default in `AppPreferences.registerDefaults()`.
3. Add a typed accessor in `AppPreferences` if runtime code consumes it.
4. Add the corresponding `@AppStorage` binding and UI in `SettingsView` when user-configurable.
5. Verify the default and persisted-value behavior manually.

When adding source files under the existing `TextExtractor` source directory, XcodeGen includes them automatically. For new targets, resources, entitlements, packages, or build settings, edit `project.yml` and regenerate the project. Review generated diffs and do not include unrelated Xcode user-state changes.

Do not change the bundle identifier, deployment target, sandbox state, entitlements, signing configuration, privacy usage strings, or package versions as a side effect of unrelated work. Those changes affect permissions or distribution and require explicit scope and validation.

## OCR-specific guidance

- `VisionTextExtractor` is the production engine and must preserve generic Vision OCR as the compatibility fallback.
- `TextPostProcessor` owns reading order, right-to-left line ordering, whitespace normalization, and line-break preservation. Keep post-processing conservative; extracted text should not be semantically rewritten.
- Structured OCR should be preferred only when it demonstrably preserves useful structure such as tables or document sections. It must fall back to generic OCR when unavailable or when structured recognition fails and generic text exists.
- Test OCR changes with representative images: light and dark UI, Retina screenshots, terminal text, mixed languages, right-to-left text, multiline paragraphs, tables, low contrast, and an image containing no text.
- Never log recognized text or captured image contents by default; both may contain sensitive user data.

## Validation expectations

For every Swift change, run the unsigned Debug build. Run tests when a test target exists or is introduced.

For capture, OCR, preferences, shortcut, clipboard, permissions, or launch-at-login changes, also report the relevant manual checks performed and any checks that require the user to run the built app. Important manual scenarios are:

- Trigger capture from both the menu and configured global shortcut.
- Complete a selection and confirm the expected text replaces the clipboard.
- Cancel the selector and confirm the existing clipboard is untouched.
- Confirm no `textract-*.png` temporary files remain after success, cancellation, or error.
- Exercise no-text and capture-permission failure behavior.
- Verify settings persist across relaunch.
- Verify generic OCR on macOS 14-compatible code paths and structured/automatic modes on macOS 26 when applicable.

Permission prompts, global shortcuts, launch-at-login registration, signing, notarization, and behavior on a clean Mac cannot be fully validated by a compile-only build. State these limitations explicitly in the handoff.

## Agent workflow

- Inspect the relevant files and `git status` before editing. Preserve existing user changes and avoid unrelated cleanup.
- Make the smallest coherent change that satisfies the request.
- Add or update tests for extracted pure logic and regressions when practical. Do not claim test coverage that does not exist.
- Keep `README.md` synchronized when setup, supported systems, user workflow, or architecture changes.
- Keep `PRODUCTIONIZATION.md` synchronized only when release/signing work changes its checklist.
- End each task with a concise summary of files changed, verification run, and remaining manual validation or known limitations.
